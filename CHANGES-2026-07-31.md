# NGH site update — Guru Hub, birthday request review, single sign-on (2026-07-31)

## New files
- `site/guru.html` — 🦦 **Guru Hub**: single staff landing page. One login (12h), at-a-glance
  counts (pending bookings, new birthday requests, radar pipeline, live + draft events), tiles
  to every staff tool, and the **Birthday Requests** review panel
  (New → Contacted → Confirmed / Declined / Archived, staff notes, reply/copy, link-to-booking).
- `site/guru-common.js` — shared admin auth + Guru nav bar. The admin token now lives in
  `localStorage("ngh_admin_token")` shared by ALL staff pages; legacy sessionStorage keys are
  mirrored for back-compat. Injects the staff nav bar on every signed-in staff page.

## Modified
- `netlify/functions/birthday.mjs` — birthday requests are now SAVED to the database
  (`birthday_requests` table, ids `BDAY-…`) before the emails go out. New admin API:
  `GET /api/birthday` (list) and `PATCH /api/birthday/:id` ({status, staffNotes, linkedBookingId}).
  Staff email now links to the Guru Hub.
- `netlify.toml` — added `/api/birthday/*` splat redirect for the PATCH route.
- `site/booking.html` — uses shared auth; **?admin=1 skips the code gate when already signed in**
  (single sign-on); logout signs out everywhere.
- `site/guru-schedule.html`, `site/guru-radar.html`, `site/checkin.html` — same shared auth
  (check-in no longer keeps its own separate token key).
- `site/robots.txt` — staff pages disallowed.

- Footer "Guru Console Login" / "Staff Login" links on index, ngh, events, library, video-game,
  and terms pages now point to `guru.html` (the Hub) instead of the booking console.

## Notes
- Requests submitted BEFORE this deploy exist only as emails to ADMIN_EMAIL (nothing was stored
  server-side until now). Your test request is in that inbox.
- The `birthday_requests` table creates itself on first request — no migration needed.
- Confirming a birthday still requires creating the booking in the console (that is what holds
  the room); the Hub links the two via the booking ID.
- Deploy: commit + push → Netlify auto-deploys. No new environment variables required.
